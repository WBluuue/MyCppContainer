4. Engineering standards
- Prefer simple C++20 designs and explain deliberate deviations from std::vector semantics.
- Maintain explicit invariants: typically 0 <= size_ <= capacity_; distinguish allocated raw storage from constructed T objects; only destroy objects whose lifetimes have begun.
- Respect alignment, allocation/deallocation pairing, RAII, nontrivial types, exception safety, and the danger of implicit shallow copies for owning pointers.
- For container raw-storage allocation, prefer std::allocator<T>/`std::allocator_traits` initially unless explicitly instructed otherwise; avoid new T[n] as a substitute for raw uninitialized capacity.
- For single-object UniquePtr ownership, adopt an already constructed object and pair scalar new with scalar delete under the default deletion policy. Do not allocate/copy T while adopting or observing it. Owned pointers have one deleting owner; get and dereference only borrow access. Arrays and incompatible allocation/deletion pairs are outside the current contract.
- Never silently use memcpy or memmove to relocate arbitrary T. Discuss appropriate move/copy semantics and exception guarantees when that milestone arrives.
- For performance work, benchmark in a suitable optimized build; describe environment and methodology; avoid invented performance numbers.
- Keep CMake target-based. Reuse Catch2/CTest, and preserve existing smoke tests. Favor targeted boundary tests, non-default-constructible and throwing/nontrivial types when relevant.
- Do not expand into DPDK, RDMA, threading, networking, lock-free, or other advanced components during the initial Vector phase.

U2 contract and preparation:
- Single goal: transfer deletion responsibility between same-type owners without allocating, copying, moving, or reconstructing T. Implement `UniquePtr(UniquePtr&&) noexcept` and `UniquePtr& operator=(UniquePtr&&) noexcept`, replacing their current deleted declarations. Keep copy construction/assignment deleted. No public release/reset/swap, custom deleter, or factory is required yet.
- Move construction: destination receives exactly the source's stored pointer and source becomes nullptr/false. Moving an empty owner yields an empty destination. No T destructor runs during the transfer; only the eventual owning destination deletes the resource. Both source-before-destination and destination-before-source destruction orders must be safe.
- Move assignment between distinct owners: delete the destination's previously owned object exactly once, transfer the source pointer unchanged, empty the source, and return *this by reference. Cover all empty/owning combinations. An empty source clears an owning destination; a moved-from owner remains valid and can accept another move assignment. Existing borrowed pointers to the transferred T still identify that same live object, but old destination-object pointers are invalid after deletion.
- Self-move assignment is explicitly a no-op: preserve pointer/value/nullness, perform no T destruction or construction, and return *this. Compare owner identity before any destructive work; comparing resource values is not a substitute for this ownership contract. Do not model two distinct owners of one raw pointer as a valid test input.
- Both moves are noexcept under the current default deletion policy and nonthrowing T-destructor assumption. Moving ownership must work even when T itself is noncopyable/nonmovable. A const source owner cannot surrender ownership; do not add converting moves or const-rvalue move overloads. The pointer transfer is constant work, while move assignment also incurs the old object's destruction/deallocation cost.
